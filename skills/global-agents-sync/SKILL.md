# 全局 AGENTS.md 维护

全局文件负责生效，仓库固定文件保存当前版本，Git 历史保留修改前后内容。默认只在当前分支本地提交，不 push。

固定位置：

- 生效文件：`/Users/liushen/.codex/AGENTS.md`
- 维护仓库：`/Users/liushen/git/gem-prompts`
- 备份文件：仓库内 `coding-agents/Codex-global-AGENTS.md`

## 简洁流程

1. **读取并检查现场。** 读取当前全局文件和仓库备份，明确本轮要改什么。在维护仓库检查当前分支、工作区、暂存区、upstream 和未推送提交；后续 Git 命令均在该仓库执行。保护已有改动，不覆盖来源未确认的备份改动；无关内容能隔离就继续，无法隔离则停止提交。
2. **确保修改前原文已提交留档。** 将当前全局文件与 `git show HEAD:coding-agents/Codex-global-AGENTS.md` 按字节比较。相同就沿用已有基线，不重复备份或提交；不同则先把当前全局原文同步到备份文件，核对一致后，单独本地提交 `docs(agents): 备份当前全局协作规则基线`。本轮只做备份时，到此结束。
3. **修改并同步。** 只调整用户要求的条款，融合现有表达，不堆重复规则。保留修改前内容用于核对；写入前若文件已被其他操作改动，先重新核对，不能直接覆盖。将完成的新文本写入全局文件和固定备份文件，回读并用 `cmp` 或字节比较确认一致，检查差异没有混入范围外修改。不额外生成日期版本、校验报告或常驻脚本。
4. **验证并本地提交。** 执行 `git diff --check`，按下方提交检查提交备份文件；提交后确认全局文件、仓库文件及 `HEAD` 中的备份逐字节一致，本轮文件无未提交改动。纯文档无需 build/test；内容未变化时不创建空提交。

## 每次提交的必要检查

- 只用 `git add -- coding-agents/Codex-global-AGENTS.md` 暂存备份，不使用 `git add .` 或 `git add -A`。
- 检查 `git diff --cached --name-only`，确保本次提交仅含该文件；若已有无关暂存内容，不替用户取消暂存，也不夹带提交。
- 执行 `git diff --cached --check`，核对暂存内容等于本次要保存的全局版本，再用 `docs(agents): 中文摘要` 提交。
- 如本轮还明确要求修改其他 Skill，在各自所属仓库单独验证和提交。

全局文件写入或 Git 提交受沙箱限制时，为该具体操作申请所需执行权限；这不改变本轮业务范围。默认不 fetch、不 rebase、不 push；用户另有明确要求时再按适用的 Git 规范处理。

交付简述修改内容、一致性检查结果、基线及新版 commit（如有）和是否 push；不把规则是否改善实际业务表现当成文件一致性检查的结论。
